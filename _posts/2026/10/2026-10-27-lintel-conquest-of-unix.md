1990 年代初，要买一台能干重活的服务器，答案几乎只有一个：一台装着 UNIX、跑在 RISC 芯片上的专有整机。Sun 的 SPARC 配 Solaris、IBM 的 POWER 配 AIX、惠普的 PA-RISC 配 HP-UX，每一套都是软硬件打包出售的封闭体系，动辄数十万美元，买进去就很难再换出来。

到了 2000 年代中期，同类负载的主流选择已经变成了 x86 加 Linux。

有意思的是，这次转变背后没有哪一次决定性的技术突破。x86 的性能是一点点追上 RISC 的，Linux 也是一点点变完善的。真正起作用的是三方：Intel 的芯片、微软的 Windows NT、自由软件社区的 Linux。它们原本各打各的，却在同一个方向上推了十几年，最后把一套以垂直整合为核心的商业模式挤出了主流市场。

视频作者给这个组合起了个名字：**Lintel**，即 Linux + Intel。一个原本被当作"PC 玩具"的芯片架构，配上一个不属于任何公司的操作系统，最后接下了原本属于昂贵 UNIX 机器的活。

## 1990 年代初：一个垂直整合的王国

先把"服务器"这个词拆开。视频给了一个大致的三层结构，这三层对性能、可靠性和价格的要求差别很大，后来也成了不同技术路线交手的战场。

最底层是工作站，也就是性能较强的桌面机，用来做图形、科学计算这类重负载，顺便在局域网里提供一两个文件服务，算是低端服务器。往上是中端服务器：由多颗 CPU 组成的机箱级系统，跑数据库、文件存储和复杂业务应用，通过网络给大量客户端提供算力。最上面是核心的一层：多 CPU、64 位寻址、虚拟化、大容量内存的大型机，跑最关键的事务处理。

这个划分并不严格，但不同层级的客户对"够用"的标准不一样，这就给了后来者一条从下层切入、逐层往上打的路。到 1990 年代中后期，这些机器又多了一个用途：托管网站。互联网热潮把网站托管做成了一个巨大的市场，跑一个网站其实用不着高端大型机，可当时的默认做法还是买 UNIX 服务器。

这一时期的市场被几家垂直整合的厂商瓜分。所谓垂直整合，就是同一家公司同时提供处理器、操作系统、编译器和整机，客户买到的是一整套封闭系统。视频点了四家：Sun Microsystems 的 SPARC 加 Solaris，IBM 的 POWER 加 AIX，惠普的 PA-RISC 加 HP-UX，还有从图形工作站起家的 Silicon Graphics。

![惠普 PA-RISC 处理器与 HP-UX 工作站](/img/2026/10/27/lintel-hp-parisc-hpux.jpg)

*图 2：惠普的 PA-RISC 处理器（左）与运行 HP-UX 的工作站（右）。芯片、操作系统、整机来自同一家供应商，这就是垂直整合的具体形态。（原视频 00:02:40–00:02:45）*

这些系统起价就是数十万美元，但比价格更要命的是封闭：编译器、驱动、系统库、技术支持合同全都绑在同一家供应商身上。业务系统一旦搭上去，迁移就意味着重写、重测、重新培训。视频用一句话概括这种关系：**buy in, get locked in**——买进去，就被锁死。

这种锁定靠的不是合同里的排他条款，而是技术债。私有编译器的行为差异、非标准的系统调用扩展、绑定特定硬件的驱动，再加上只有原厂工程师才熟悉的运维知识，叠在一起，一次平台迁移的隐性成本会远远超过硬件本身的差价。所以到后来，"低锁定"本身就成了可以拿来卖的产品特性。

## Intel 的飞轮，与一个真正的企业级操作系统

Intel 敢进服务器市场，底气来自它在 PC 市场的打法。视频把这套打法拆成一个自我强化的循环。

![Intel 的高销量飞轮](/img/2026/10/27/lintel-flywheel.png)

*图 3：高销量带来的不只是固定成本摊薄，还有良率学习曲线上的经验积累；省下来的现金流再投入更先进的制程，又能支撑更高的销量。*

这个循环也解释了 AMD、Cyrix 这类对手为什么就算做出相近的产品，成本上也很难追上：它们出货量小得多，良率学得也慢得多。Intel 在 PC 市场的领先因此很难被撼动。

接下来的问题是，这套玩法能不能搬到企业服务器市场。这取决于能不能找到一个够强的软件伙伴，因为服务器客户买的不是芯片，而是能跑业务系统的平台。

这个伙伴就是微软。1993 年，Dave Cutler 带队的团队发布了 Windows NT，官方说法是 New Technology。NT 和消费级 Windows 完全是两回事。视频里有个很形象的对比：当时的普通 Windows（3.x）基本上是硬嫁接在 MS-DOS 上的一层图形外壳，而 NT 是为企业环境从零重写的操作系统。

具体差在几个地方：内存保护和抢占式多任务，让一个用户进程崩了不至于拖垮整个系统；内核设计成可以在多种处理器架构上编译，而不是死绑 x86；用户、组、权限这些概念从内核层就有。微软对外宣传的也正是这三点：更强大、更可靠、更安全。

不过第一版并没有一炮而红。首发版本跑在 Intel 386 上，能用，但缺少竞争对手（IBM 的 OS/2、Novell 的 NetWare、各种 UNIX）已有的一些能力，对硬件的要求也偏高，要 16 MB 内存。1993 年 NT Server 大约只卖出 3 万套。

![Windows NT 1993 至 1994 年销量](/img/2026/10/27/lintel-nt-sales-1993-1994.jpg)

*图 4：IDC 统计的 Windows NT 工作站版与服务器版销量（单位：千套）。1993 年服务器版约 3 万套，1994 年升到 11.5 万套。（原视频 00:04:44–00:04:51）*

1994 年情况好转，微软卖出约 11.5 万份 NT 许可证。虽然还落后于同代的工作站版本，但趋势已经很明显。视频在这里开了个玩笑，说微软就像"终结者"或者《Air Bud》的续集，不管怎样都会一直出下去。玩笑背后是一个实打实的商业事实：微软有本钱在一个还没赚钱的品类里连续投入好几年，直到产品成熟。

![Windows NT 1993 至 1996 年销量](/img/2026/10/27/lintel-nt-sales-1993-1996.jpg)

*图 5：同一口径延长到 1996 年，服务器版销量从 3 万套增长到约 67 万套（1996 年为估计值）。（原视频 00:07:04–00:07:11）*

## Pentium Pro 与"标准高容量服务器"

1995 年底，Intel 推出了它眼中第一颗真正能打进服务器的芯片：32 位的 Pentium Pro。规格对比如下：

| | Pentium | Pentium Pro |
| --- | ---: | ---: |
| 晶体管数 | 310 万 | 550 万 |
| 主频 | 约 60 MHz | 约 150–200 MHz |
| 发布年份 | 1993 | 1995 |

真正让业界震动的是基准测试，而不是频率。在某些整数基准上，Pentium Pro 小幅超过了当时最快的 RISC 芯片。虽然 MIPS R10000 这类更快的 RISC 很快又追了上来，但这次测试打破了一个长期的认知：x86 不再只是"桌面架构"。

![SPECint95 与 SPECfp95 对比](/img/2026/10/27/lintel-specint95-pentium-pro.jpg)

*图 6：1995 年的 SPECint95 / SPECfp95 对比。Pentium Pro 在整数上已能与同期 RISC 同场竞争，浮点上仍明显落后。（原视频 00:05:25–00:05:31）*

浮点落后在当时并不致命，因为企业服务器上的多数负载，比如数据库事务、文件服务、Web 服务，主要吃整数和内存访问。真正起作用的是性价比：只要性能够用、价格又低一个数量级，客户就会重新算账。后面的故事基本都建立在这一点上。

光有芯片还不够。客户买的是整机，而整机的集成工作又琐碎又耗时。所以 1995 年中，Intel 开始向合作伙伴分发"标准高容量服务器"（Standard High Volume Server，SHV）的参考设计板：支持 1–4 颗 Pentium Pro、1–2 GB 工作内存、数百 GB 存储，Intel 宣称每秒能处理 2000 笔事务。

惠普、Dell、Compaq、Gateway 2000 这些 OEM 可以直接拿这套设计来用，把上市时间压到几个月。1995 年 11 月的发布会上，基于 Pentium Pro 的整机价格区间定在 2600 美元的工作站到 2 万美元的服务器之间。

![InfoWorld 报道 Intel 推送 P6 服务器](/img/2026/10/27/lintel-intel-p6-servers-infoworld.jpg)

*图 7：1995 年 5 月 InfoWorld 的报道——Intel 向 OEM 推出完整的 P6 服务器系统方案。（原视频 00:06:09–00:06:16）*

这一步相当于 Intel 从"卖芯片"变成了"卖整机参考方案"。它绕开了传统服务器厂商的系统集成能力，让一批原本只做 PC 的 OEM 也能很快进入服务器市场。等这些 OEM 成长起来，UNIX 厂商要面对的就不只是 Intel 一家，而是一整个建立在 PC 供应链上的产业群。

再配上 1996 年的 Windows NT 4.0，这套组合开始见效。IDC 数据显示，1996 年 NT 4.0 销售额增长 85%，市场份额达到 27%。竞争依然激烈，但 Wintel 已经在服务器市场建起了一块类似 PC 市场的根据地。

## 联盟的裂缝

Wintel 是利益共同体，但两家的利益并不完全一致。下面这三处摩擦，当时看只是商业纠纷，回头看却直接把 Intel 推向了 Linux。

**NSP 事件。** 1995 年，Intel 推出一个叫"原生信号处理"（Native Signal Processing，NSP）的多媒体软件标准，思路很直接：把一部分音视频计算从专用芯片搬到 CPU 上，用软件和 API 来实现。对 Intel 来说，这既能让用户感觉到"新 CPU 更快"，也能扩大 x86 的用武之地。

微软的反应非常激烈。在微软看来，NSP 是一种"中间件"，绕过操作系统直接对接硬件和应用，等于闯进了 Windows 的地盘。微软高管明确表示不会支持，比尔·盖茨还专门给安迪·格鲁夫发邮件表达不满。

![InfoWorld 关于 NSP 的报道](/img/2026/10/27/lintel-intel-nsp-infoworld.jpg)

*图 8：1995 年 InfoWorld 的报道"NSP expected to get show of support at WinHEC"，文中列出把多媒体计算交给 CPU 的成本对比，即视频所说的 NSP 主张。（原视频 00:07:17–00:07:23）*

最后以 Intel 退让收场。NSP 事件后来在微软的反垄断诉讼中被公开，成了微软利用平台地位打压合作方的例证之一。两家公司对外都淡化处理，但 Intel 从中读到了一个很清楚的信号：它的"伙伴"随时可以用平台权力否掉它的战略。

**NT 的可移植性。** 第二处摩擦更隐蔽。和消费级 Windows 不同，NT 从设计之初就是可移植的。绝大多数 NT 实例跑在 x86 上，但它同样支持 DEC 的 Alpha、IBM 与 Apple 的 PowerPC，以及 MIPS。

![NEC 的 Windows NT 广告](/img/2026/10/27/lintel-nec-nt-mips-ad.jpg)

*图 9：1993 年 11 月 NEC 在 InfoWorld 投放的广告，标题是"The brains behind Windows NT"，宣传其 MIPS 芯片可以运行 NT。（原视频 00:08:40–00:08:46）*

对客户来说这是好事，买 NT 不会被绑死在某一种芯片上。对 Intel 来说却是战略隐患：微软还在不断签新的芯片支持协议，等于在 Intel 身边布了一圈备胎。如果 NT 成了服务器操作系统的事实标准，微软完全可以把 x86 降格成"众多架构之一"，Intel 在 PC 市场攒下的规模优势就会被稀释到一个多架构混战的市场里。说白了，Intel 最重要的护城河，要由合作伙伴来决定守不守得住。

**节奏错配。** 就算不谈战略博弈，两家公司的产品节奏也天生对不上。Intel 跟着摩尔定律走，大约每两年出一代更快更好的芯片；微软大约每三到五年才发一个新版 Windows，而且新系统未必马上能用满新芯片的能力。

视频举了两个很有说服力的例子。第一个是 32 位：Intel 1985 年就推出了 32 位的 386，微软直到 1995 年的 Windows 95 才拿出面向消费者的 32 位操作系统，整整晚了十年。

第二个更具体。Pentium Pro 开发期间，微软在多次会议上告诉 Intel，下一代 Windows（代号 Chicago，也就是后来的 Windows 95）会是纯 32 位，遗留的 16 位代码全部去掉。Intel 据此把 Pentium Pro 的优化重点放在 32 位性能上。结果 1994 年微软公开宣布，Chicago 的图形显示接口，也就是操作系统的关键部分，仍然保留 16 位。

![Pentium Pro 的 16 位遗留问题](/img/2026/10/27/lintel-pentium-pro-16bit-headline.jpg)

*图 10：1995 年 11 月《Daily Record》的报道标题——"Pentium Pro sets PC standard — But Intel's speedy new chip lags on older 16-bit software"。（原视频 00:10:36–00:10:41）*

这时 Pentium Pro 已经到了开发后期，改设计来不及了。芯片上市后，媒体在消费级桌面场景下测出很差的图形性能，Intel 替微软的设计决策背了锅。

**SMP 天花板。** 第三个矛盾落在服务器最核心的指标上：多处理器扩展能力。NT 4.0 单个操作系统实例最多支持 4–8 颗处理器，而当时一些 UNIX 变体能支持到 64 颗。所以 NT 在架构上就被挡在了高端市场门外，客户要在单机里跑大型数据库，还是只能选 UNIX。

![各种操作系统的 SMP 支持上限](/img/2026/10/27/lintel-smp-support.png)

*图 11：单个 OS 实例支持的处理器数对比，数据取自视频正文。NT 4.0 的上限、Linux 2.2 的上限，以及随后两代内核的改进，构成了后面竞争的关键变量。*

这些错配从哪来？视频给的解释很到位：两家公司的增长模型不一样。

| | Intel | Microsoft |
| --- | --- | --- |
| 收入来源 | 卖最新的芯片 | 服务整个已安装基础 |
| 对软件的要求 | 需要能吃掉新算力的软件 | 需要向后兼容、覆盖尽可能多用户 |
| 发布节奏 | 约每两年一代 | 约三到五年一版 |
| 对旧平台的态度 | 希望用户尽快换新 | 必须照顾存量客户 |

微软并不是不肯投入，开发一个新版 Windows 要几千名员工，花费可能高达数十亿美元。问题出在软件本身的属性上：它必须照顾存量。两种模型单看都合理，放在一起就会不停摩擦。那 Intel 还有什么牌可打？1990 年代后期，一个很有分量的新候选进入了它的视野：Linux。

## GNU 与 Linux：一个没有所有者的替代品

讲 Intel 怎么发现 Linux 之前，先说说 Linux 是怎么来的。视频把这段压缩在几分钟里，但其中每个环节都影响了 Linux 后来的治理结构。

1984 年 1 月，麻省理工学院的程序员 Richard Stallman 正式启动了一个替代 UNIX 的项目。他为什么要这么做，得从 MIT 人工智能实验室的一段往事说起。

Lisp 原本是早期 AI 研究里一件优雅的工具。等商人们意识到 Lisp 和它背后的 AI 可以做成一个大产业，实验室就分裂成了两家公司：Symbolics 和 Lisp Machines Inc.。Symbolics 融了数百万美元，想成为"那个时代的英伟达"，把实验室里最顶尖的黑客全挖走了，只留下一个空壳。

![Symbolics 与 LMI 的标志](/img/2026/10/27/lintel-symbolics-lmi.jpg)

*图 12：Symbolics 与 Lisp Machines Inc.（LMI）的标志，这两家公司由 MIT AI 实验室分裂而来。（原视频 00:12:27–00:12:33）*

Stallman 始终没能原谅这件事。视频引用了他后来说的一句话：*"Everything's dying."*（一切都在死去。）黑客社区的消亡让他很失落，于是他决定建立一个新的社区，基础就是"自由软件"这个概念。

1983 年底，Stallman 启动了一个构建自由操作系统的项目。它遵循 UNIX 的设计原则（模块化、可移植），但不复制 UNIX 的代码，以避开商业秘密问题。项目叫 GNU，是 "GNU's Not UNIX" 的递归缩写。接下来几年，Stallman 和社区把工具链的各个部分都做了出来：编辑器、编译器、shell 和各种工具程序。

整个系统只差一样东西：内核。

![内核在系统中的位置](/img/2026/10/27/lintel-kernel-diagram.jpg)

*图 13：内核位于应用与硬件之间，负责内存管理、CPU 时间分配、磁盘与设备访问。视频特意强调，内核是操作系统真正的心脏。（原视频 00:13:33–00:13:38）*

说内核是心脏一点也不夸张。内存怎么分配、每个进程分到多少 CPU 时间、磁盘空间怎么管，都归内核负责，它把操作系统的其余部分和硬件隔开。没有它，GNU 就只是一套漂亮但没有心脏的工具。

最后补上内核的，是一个 21 岁的芬兰本科生。Linus Torvalds 受教学用 UNIX 系统 MINIX 的启发，1991 年 8 月在 MINIX 的 Usenet 新闻组发帖，说自己在做一个自由的操作系统，想征求功能建议。帖子吸引来了 MINIX 生态的贡献者，最后发展成了一个独立的项目：Linux。

Linus 的角色很快从写代码变成了审阅别人的贡献、合并进代码库。这种后来被概括为"集市"的模式，让 Linux 交付新代码的速度比公司还快。1991 年 10 月，第一个可用版本发布；1992 年，0.12 版采用了 Stallman 的 GPL 许可证。

![Torvalds 谈 GPL](/img/2026/10/27/lintel-torvalds-gpl-cio.jpg)

*图 14：CIO 的采访标题——"Linus Torvalds says GPL was defining factor in Linux's success"。Torvalds 在采访中反复强调，GPL 防止了碎片化。（原视频 00:15:13–00:15:19）*

Linux 没有重蹈 UNIX 的覆辙，很大程度上要归功于 GPL 的条款。GPL 规定：任何人都可以阅读和修改代码，但只要分发修改后的版本，就必须同样开源发布。这带来了两个结果。

一是防止碎片化。公司不能把内核拿去加点自己的东西，再当成闭源的竞争产品卖，这就避开了 UNIX 当年分裂成三十多个互不兼容变体的命运。二是保证贡献回流。任何公司对内核的改进都会惠及所有人，不会被锁进私有分支，所以大公司才愿意投入，IBM 后来有数百名员工给内核贡献代码。Torvalds 后来多次说过，选 GPL 是他做过的最正确的决定。

反过来看也成立：大公司之所以肯接纳 Linux，正是因为 GPL 让它们确信，自己的投入不会被竞争对手独占。所以 GPL 在这里起的是产业治理的作用，远不止是一条法律细节。

## 发行版与 Red Hat：把内核变成产品

Linux 只是一个内核。视频打了个很贴切的比方：内核是汽车的引擎，非常重要，但你还得有整辆车的其他部分。

早期极客自己组装系统没问题，但要普通用户先"造一辆车"再开，显然不现实。于是有了发行版：把 Linux 内核和 GNU 项目或其他自由软件的工具打包在一起，做成一套稍微好用些的操作系统。视频又打了个比方，说这就像高中时大家互相传的混音带，把喜欢的歌按某种顺序拼在一起。好的发行版能火到可以赚钱，它的商业模式被形容为"卖瓶装水"：包装不同，水是同一份。

早期有代表性的发行版有 Slackware、Debian，以及后来最重要的 Red Hat。Red Hat 由 Marc Ewing 在 1993 年创立。Ewing 很早就开始用 Linux，用了一阵发现，自己花在管理 Linux 机器上的时间比写代码还多。于是他做了一个发行版，就在他公寓的备用卧室里，那间公寓靠近杜克大学。名字来自他大学时戴的一顶红白条纹长曲棍球帽。

Red Hat 做的事，就是把 Linux 变成一个更专业的产品。最典型的例子是 Red Hat Package Manager（RPM）：用户可以很方便地安装、删除、更新软件包，比如 Web 服务或 FTP 服务。

![Red Hat Linux 6.1 零售包装盒](/img/2026/10/27/lintel-redhat-box.jpg)

*图 15：Red Hat Linux 6.1 的零售包装盒。发行版可以刻成光盘、装盒、在零售店销售——这是 Linux 走向主流用户的具体形态。（原视频 00:18:31–00:18:36）*

1995 年，Ewing 和同事 Robert Young 成立了 Red Hat 公司，靠卖光盘以及配套的培训、教育和客户支持赚钱。最初几年，Linux 的用户主要是技术很强的黑客和穷学生；Red Hat 和其他商业发行版（如 Caldera）起来之后，才把这个系统带出了小圈子，进入企业的主流视野。

企业客户要买的从来都不是一个"内核"，而是一套有支持合同、能运维的系统，发行版公司正好补上了这块空缺。

## Linux 的早期市场：价格只是入场券

Linux 起步很小，但涨得很快。1992 年初可能只有几百名用户，1996 年大约 100 万到 200 万，到 1997 年中，全球用户保守估计在 300 万到 500 万之间。同期 Windows 约有 1 亿用户，Macintosh 有 5000 万以上，相比之下 Linux 的绝对规模还很小，但增速完全不是一个量级。

价格当然是原因之一，而且差距极大。一张 Red Hat 光盘加包装盒在零售店卖约 50 美元；Windows NT 许可证从单份升级的约 150 美元到 10 个座位的约 1100 美元不等；含软硬件的 UNIX 系统则要 2.5 万到 25 万美元，甚至更多。

![操作系统价格对比](/img/2026/10/27/lintel-price-ladder.png)

*图 16：同一台服务器上操作系统的价格对比，数据取自视频正文，横轴为对数刻度。*

视频引用了一个具体案例：1997 年《Byte》杂志报道，伊士曼柯达的一位系统顾问在一个 Photo CD 相关项目里装了 Linux，因为不用再买高价的 UNIX 方案，公司省下了 1 万美元。

但企业和机构选 Linux，也不全是图便宜。

一位用户说 Linux 几乎"不会崩溃"（crash-proof），这直接换来了更高的生产力。对高级用户来说，能看源代码是 Windows 永远给不了的，这意味着可以按需改造系统。有人把 Linux 移植到了 Palm Pilot 上；洛斯阿拉莫斯的研究人员用 Linux 把 68 台 PC 联起来，模拟原子冲击波。

![Philadelphia Inquirer 关于 Linux 的报道](/img/2026/10/27/lintel-linux-philadelphia-inquirer.jpg)

*图 17：1996 年 5 月《Philadelphia Inquirer》的报道，讨论 Linux 的低成本与可获得性。文中提到"最好的 Linux 来源是一家叫 Red Hat 的公司"。（原视频 00:17:50–00:17:54）*

视频也没回避 Linux 当时的短板。一是应用太少，没有像样的 Microsoft Office、Visual Basic 或其他商业软件。视频对此的点评挺有意思：《Byte》指出这一点后，紧接着补了一句"Linux 确实包含大量可以用来自己写应用的工具"，这恰好说明了当时 Linux 读者是些什么人。二是支持困难，出了问题该查什么文档、该打给谁，而这正是 Red Hat、Caldera 这类公司能插手的地方。三是名声问题：Linux 和 UNIX 并没有直接血缘，却常被归为一类，连带继承了 UNIX"晦涩难用"的名声。

更微妙的是管理层的偏见。尽管 Linux 增长很快、不少知名机构在用、性价比也确实明显，高管层里仍然存在负面印象。一位经理可能会问："你怎么能把关键服务器交给它？"而这时候，他公司某台机器上很可能已经跑着 Linux 了。一位匿名系统管理员 1998 年对《旧金山纪事报》说的话很能代表这种拉扯：

> "很多管理层不信任 Linux，因为它是免费的。但他们让我负责运行服务器，那我就用最有效的。最有效的是 Linux。"

这种拉扯也预示了 Linux 后来的路数：自下而上。价格让它进了机房，可靠性让它留了下来，管理层的态度则是最后被既成事实扭过来的。

## 1998：Intel 发现 Linux

1998 年初，Intel 开始收到来自全国各地的奇怪请求。费米国家加速器实验室（Fermi National Accelerator Lab）等机构的工程师和研究人员，要求 Intel 把它的数学库移植到 Linux 上。

此前 Intel 和 Linux 几乎没什么交集，最多修过一两个 bug。这些请求让 Intel 去摸了摸底：它向那些给小型 ISP 等客户做白牌服务器的 OEM 打听，得到的反馈是 Linux 的增长正在加速。具体数字很有冲击力：**大约 20% 的公共 Web 服务器运行 Linux**。考虑到这个操作系统在桌面上几乎没有存在感，这个份额高得出乎意料。

![Oracle 宣布支持 Linux](/img/2026/10/27/lintel-oracle-linux-cnet.jpg)

*图 18：CNET 1999 年 7 月 20 日的短讯"Oracle offers Linux"，报道 Oracle 8i 可免费下载。视频用这张页面来说明数据库厂商的转向；正文里的 1998 年 7 月则是 Oracle 首次宣布移植 Oracle8 的时间。（原视频 00:25:05–00:25:09）*

消息一路传到了安迪·格鲁夫那里。据视频描述，他用相当"丰富多彩"的语言表示，得对此做点什么。

于是 Intel 高管找上了 Red Hat，开了一系列会，想弄明白这家公司是怎么运作的。结果他们有点懵：Red Hat 并不拥有核心软件产品背后的知识产权，而这份软件任何人都能免费拿到。这怎么赚钱？又怎么投资？

Red Hat 的人接着解释。CEO Robert Young 喜欢拿番茄酱打比方：谁有番茄、糖和醋都能做番茄酱，但亨氏占了 80% 的市场。意思是，产品本身可以复制，但品牌、渠道、支持和服务撑起来的商业位置不好复制。

与此同时，Intel 内部的 Linux 支持者也在分享他们从 ISP 渠道拿到的采用数据。最终，Intel 管理层被说服了。

Intel 当时还有一个更具体的动机。它正在开发一款叫 Merced 的新芯片，是 64 位 IA-64 服务器架构的第一个实现，后来命名为 Itanium，据说速度极快。但 Intel 一直担心，NT 会把它的能力捆住，就像 32 位时代那样一耽误就是十年。这个担心还有新的佐证：微软的下一代 NT（当时叫 NT 5.0）从 1998 年推迟到 1999 年，之后又一再延期，最后改名 Windows 2000。

所以 Intel 要的不只是"x86 上多一个能跑的操作系统"，而是一个自己能深度参与优化的系统：能及时吃掉最新芯片的能力，也不会被某个伙伴卡脖子。Linux 正好两条都满足：代码开放，也没有一个能对它行使否决权的所有者。

## Linux 之夏与 Intel 的押注

1998 年夏天，多家大公司接连发布和 Linux 有关的公告，这段时间后来被称作"Linux 之夏"。

6 月，以保守著称的 IBM 宣布在电子商务工具套件里纳入开源 Web 服务器 Apache。Apache 本身不是 Linux，但绝大多数 Apache 实例都跑在 Linux 上。IBM 早在 1996 年就用 Apache 支撑过亚特兰大夏季奥运会官网，这次则是正式背书，开源软件第一次在企业市场站住了脚。

7 月初，Oracle 还站在另一边。《InfoWorld》7 月 6 日发了一篇题为"Linux not yet critical mass"的文章，Oracle 和 Sybase、Informix 都在文中表示没有为 Linux 发布数据库软件的计划，理由是没看到客户有强烈需求。

仅仅三天后，Oracle 就宣布要把 Oracle8 数据库移植到 Linux。这次急转弯的一个重要原因，是 7 月在圣克拉拉举行的一场叫"Linux 的未来"的座谈会。

![Linux 的未来座谈会](/img/2026/10/27/lintel-future-of-linux-panel.jpg)

*图 19：1998 年 7 月 14 日在圣克拉拉举行的"Linux 的未来"座谈会记录。主办方预计到场人数远超预期，实际约 700–900 人到场。（原视频 00:25:16–00:25:21）*

900 多人到场去看 Torvalds 等人。会上讨论了开源是不是只是一阵风，并号召用户推动应用厂商移植到 Linux。后来人们把这场座谈会看作一个重要的转折点。

9 月，更多厂商跟了进来。到 1998 年 9 月，已经有多家大公司提供 Linux 移植版本，包括 Computer Associates、Corel 和 Informix。

Intel 也去了 7 月那场座谈会。Intel 的 Sunil Saxena 在会上做报告，指出 Linux 正在成为 ISP 的首选操作系统，也点出了它的几个弱点：可扩展性、高端硬件驱动、大内存支持，并强调 Intel 希望支持 Linux。这些话很快落到了实处：1998 年 9 月 29 日，Intel 宣布与浏览器公司 Netscape、风投 Benchmark 和 Greylock 一起投资 Red Hat。

![Intel 关于 Linux 支持的新闻稿](/img/2026/10/27/lintel-intel-redhat-press-release.jpg)

*图 20：Intel 1998 年 9 月 29 日的新闻稿，宣布在 ISPCON Fall '98 上推出一系列面向 ISP 的举措，其中包括对 Linux 社区的支持。（原视频 00:26:23–00:26:28）*

Intel 的表态有几层意思：希望 Intel 芯片跑 Linux 的效果和跑 Windows NT 及其他系统一样好；和 Red Hat 合作提供技术贡献，给 Linux 社区指派专职的 Intel 工程联络人；加入 Linux International，一个早期的全球性 Linux 推广组织。

投资公告之后，又倒下了一张关键的多米诺骨牌，视频称之为"关键但被低估"。Benchmark 的一位合伙人同时是戴尔的董事，通过他，Red Hat 见到了 Michael Dell。双方聊了 Linux 在服务器上的增长、市场格局会怎么变，以及 Linux 有没有可能拿下桌面。戴尔最后投资了 Red Hat，更重要的是，戴尔在 1999 年初宣布将在工作站和服务器上预装 Linux，成了第一家这么做的整机大厂。

![戴尔预装 Red Hat 的新闻稿](/img/2026/10/27/lintel-dell-redhat-press-release.jpg)

*图 21：Red Hat 1999 年 2 月 4 日的新闻稿——戴尔将预装 Red Hat Linux。这是主流系统厂商第一次在整机上预装 Linux。（原视频 00:27:08–00:27:12）*

预装比投资的分量重得多。投资只是一笔财务操作，预装则意味着 Linux 和 Windows、NetWare 一起进了采购选项：客户买来服务器，开机就是 Linux，用不着自己折腾安装。

微软的反应则从激烈慢慢收敛。Red Hat 高管在《Under the Radar》一书中回忆，Intel 宣布投资后微软"went ballistic"（暴跳如雷），那个周末 Intel 高管接到了好几通来自微软对口人员的愤怒电话。

但 1998 年的微软已经不像 1997 年那样可以随心所欲了。1998 年 5 月，美国司法部以垄断行为起诉微软，矛头主要指向浏览器大战期间把 Internet Explorer 和 Windows 捆绑的做法。诉讼和随之而来的审查逼得微软收敛。它的公开回应很巧妙：发声明把 Red Hat 说成是"微软并没有垄断操作系统"的证据；更有意思的是，微软后来还拿 Linux 当证据，证明操作系统市场竞争充分，政府不该拆分它。

内部可就没那么轻松了。1998 年 10 月，一组后来被称为"万圣节备忘录"（Halloween Memos）的微软内部文件泄露，里面把 Linux 这类自由软件的兴起称为对 Windows 的"长期可信威胁"。

![万圣节备忘录公开页面](/img/2026/10/27/lintel-halloween-documents.jpg)

*图 22：The Halloween Documents 公开页面。这些内部文件分析了开源开发模式的优势，并把 Linux 视为长期威胁。（原视频 00:28:29–00:28:33）*

据称微软随后组建了一支"Linux 攻击小组"，想说服客户 Linux 还没准备好。他们上线了一个叫"Linux Myths"的网页，号称要"从炒作中退后一步，看看现实"，逐条反驳 Linux 拥趸常挂在嘴边的"神话"，比如"Linux 比 Windows NT 4 性能更好""Linux 比 Windows NT 4 更可靠""Linux 是免费的"。

![微软的 Linux Myths 网页](/img/2026/10/27/lintel-linux-myths-webpage.jpg)

争议最大的一次发生在 1999 年 4 月：微软资助第三方实验室 Mindcraft 做基准测试，结果显示 NT 在文件服务器场景下比 Linux 快 2.5 倍，在 Web 服务器场景下快 3.7 倍。

![Mindcraft 基准测试](/img/2026/10/27/lintel-mindcraft-benchmark.jpg)

Linux 支持者随即指出测试不公平，尤其是 Linux 一方用的是没调优过的旧版内核和配置。但不管争议最后怎么说，这件事本身就说明，微软已经把 Linux 当成了必须正面应对的对手。

## Port of Choice：瑞士策略与硬件补齐

面对盖茨的怒火，Intel 的应对是宣布自己"OS 中立"：Linux、Novell 的 NetWare、Sun 的 Solaris、微软的 Windows 2000，Intel 希望它们在自己的硬件上都跑得好。它甚至和另外二十家公司一起，想用一种叫 Uniform Driver Initiative 的机制统一当时三十来种 UNIX 变体的驱动模型，方便厂商给 Intel 硬件写驱动，不过这件事最后没成。

这套策略到 2010 年才被正式命名为"Port of Choice"，但 Intel CTO Pat Gelsinger 早在 2001 年就说过这是公司一贯的策略。字面意思是"移植的首选目标"：任何操作系统想覆盖最多的硬件，就得优先支持 Intel 架构。这样一来，Intel 不必再依附某一个操作系统，反倒是操作系统要来适配 Intel。操作系统厂商最后也只能接受，因为当时的 Intel 芯片没有真正的替代品。

软件之外，硬件这边也在补齐服务器需要的能力。1998 年中，Intel 推出 Pentium Pro 的后继产品 Pentium II Xeon，主攻中端工作站和服务器市场，主频更高，L2 缓存 512 KB。几个月后，1999 年 3 月，Pentium III Xeon 发布。它比前代快不了多少，但能通过名为 Profusion 的芯片组搭 8 路系统：厂商可以在一个机箱里对称地放八颗 CPU，突破了此前 4 路的天花板，而这个天花板正是当时数据中心性能问题的来源之一。

![8 路 Xeon 系统结构](/img/2026/10/27/lintel-xeon-8way-profusion.jpg)

*图 25：8 路 Xeon 系统的结构示意——八颗处理器通过 Profusion 芯片组共享内存与 I/O 总线。（原视频 00:30:57–00:31:02）*

不过 8 路能力得有操作系统配合才发挥得出来。Windows NT/2000 支持，Linux 当时还有问题。这也是 Intel 要在两个操作系统上同时下注的原因：硬件已经就位，软件跟不跟得上，决定了它卖不卖得出去。

高端 UNIX 服务器还握着一些关键优势，最突出的是内存寻址能力：大型数据库、数据仓库、CAD 系统需要的主内存远超 32 位 x86 的上限。但有了这两代 Xeon，中低端 UNIX 服务器的侧翼已经完全暴露。硬件补齐之后，瓶颈落到了软件上：NT 的 SMP 上限和 Linux 的 SMP 缺陷，成了下一阶段的主战场。

## Web 让天平倾斜

Sun 一开始是欢迎 Linux 革命的，这和它"开放"的口号一致：Sun 把 Java 开发工具包移植到了 Linux，还发布了能跑 Linux 的工作站硬件。给人的整体印象是，Sun 不在乎一台机器跑的是 Linux 还是 Solaris，只要是 SPARC 机器就行。

事实证明这是个误判：机器不一定非得是 SPARC。

网站服务、邮件托管、防火墙这类活，和跑数据库、分析软件不一样，可以水平切分到很多台小机器上。企业慢慢意识到，用一批 Intel 芯片加 Linux 的节点横向扩展（scale out），在财务上比纵向扩展（scale up）一台大型 UNIX 服务器划算得多。

互联网泡沫破裂后，这个趋势一下子加速了。风投枯竭，创业公司接连倒闭，大家都开始省钱：要么买倒闭公司清算出来的二手设备，要么干脆换成 Linux。

亚马逊 2001 年做了一次大规模 Linux 迁移，在季度 SEC 文件里提到，这估计每季度能省下 1700 万美元。被问到具体做了什么时，亚马逊发言人的回答很有意思：

![亚马逊转向 Linux 的报道](/img/2026/10/27/lintel-amazon-linux-2001.jpg)

*图 26：2001 年 Yahoo News 转载的路透社报道——"Amazon Says Saving Money with Shift to Linux"。（原视频 00:32:46–00:32:58）*

> "We've always been pretty closed-mouthed about technology on the back-end stuff, partly because it's pretty steep tuition and we don't want other people going to school on our tuition."

翻译过来就是：我们对后端技术一向守口如瓶，部分原因是学费很贵，我们不想让别人拿我们的学费去上学。

在线券商 E*Trade 在 2006 年公布了一份更有说服力的案例研究，对比了两套方案：

| 方案 | 硬件成本 | 可服务用户数 | 每用户成本 |
| --- | ---: | ---: | ---: |
| Sun Enterprise 4500 | $250,000 | 300–400 | 约 $714 |
| Linux + Intel 单机 | $4,000 | 180 | 约 $22 |
| Linux + Intel 两台 | $8,000 | 360 | 约 $22 |

单台 Linux 机器只能服务 180 人，看上去不如 Sun 的 300–400 人。但办法很简单：买两台。总价 8000 美元，服务 360 人，花费只有 Sun 方案的 3.2%，每用户成本差了一个数量级还多。

![每用户硬件成本对比](/img/2026/10/27/lintel-cost-per-user.png)

*图 27：按每用户硬件成本计算，scale-out 方案的差距约为 32 倍。*

![E*Trade 案例与 Sun Enterprise 4500](/img/2026/10/27/lintel-etrade-sun-e4500.jpg)

*图 28：E*Trade 2006 年的案例研究与 Sun Enterprise 4500 服务器。文中提到这次迁移每年节省约 1300 万美元。（原视频 00:33:09–00:33:16）*

从 2001 年起，搭载 Intel 芯片的 Linux 服务器逐渐能稳定地替换 Sun 的设备，从机票比价、大宗商品合约交易到金融计算，各类场景都有。

Sun 也试过自己的横向扩展产品线 Netra，2001 年的 Netra X1 售价低到 1000 美元，但通用 x86 硬件的每美元性能还是更好。视频的判断很直接：对于"从 SPARC 上的 Solaris 转向 Intel 上的 Linux"这一转变，Sun 始终没拿出像样的回应。

![服务器操作系统份额 1995 至 2000](/img/2026/10/27/lintel-server-os-share-1995-2000.jpg)

*图 29：1995–2000 年各类服务器操作系统的全球出货量份额。Linux 从 1996 年几乎为零增长到 2000 年的约四分之一，UNIX 的份额持续收缩。（原视频 00:32:21–00:32:27）*

所以真正的转折，发生在这类能水平切分的负载上：多台廉价机器在财务上完胜一台大型 UNIX 服务器，泡沫破裂又让企业更加精打细算。E*Trade 和亚马逊的例子都说明，推动替换的是单位成本上数量级的差距，而不是单机性能。

## 向上攀升：Linux 2.4 与 2.6

拿下低端市场之后，Linux 开始往上打。2000 年底，IBM CEO 郭士纳（Lou Gerstner）认为 Linux 会像互联网一样改变世界，宣布了一项大规模的 Linux 计划：投入 10 亿美元和 1500 名员工。

2001 年 1 月，Linux 2.4 发布，Red Hat 很快在后续版本里用上了它。2.4 比预期晚了一年，但确实兑现了承诺，缩小了和高端 UNIX 服务器及 NT 之间的一些性能差距，其中最关键的是多处理器支持。

1999 年 Mindcraft 测试的一个主要争议点，就是 Linux 对多处理器机器的支持。那次测试和之后的测试都显示，Linux 2.2 在单系统超过两颗 CPU 时扩展性很差，而 Windows NT 4.0 和 2000 分别支持 4 路、8 路乃至 32 路。缺了这个能力，是一个很大的短板。

于是 Torvalds 和社区着手改进。2.4 版解决了自旋锁（spin lock）等问题，让 Linux 能在一定程度上有效利用 16 甚至 32 颗处理器。视频作者也坦白说，他不确定这么高核数下实际跑得怎么样。这个改进并没有让 Linux 一夜之间能挑战高端 UNIX 机器，但有了 4 路、8 路的能力，Lintel 进军中端计算任务的路就通了。

![Linux 2.4.0 发布邮件](/img/2026/10/27/lintel-linux-2.4-announcement.jpg)

*图 30：2001 年 1 月 Torvalds 在内核邮件列表上发布 2.4.0 的邮件。通篇是自嘲式的幽默，最后一句是"别在这几天报 bug，反正我也不在乎"。（原视频 00:34:26–00:34:32）*

这时 Lintel 的经济账已经非常有说服力：一台戴尔服务器，四颗 Xeon，跑 Red Hat Linux，售价 24000 美元，是同等 Sun Fire UNIX 机器的一半，性能却一样好。

"一半价格、同等性能"之所以致命，是因为服务器采购不是一锤子买卖，企业还要付电费、机架空间、运维人力和软件许可。价格减半，同样的预算就能部署两倍的节点，或者同样的负载能省下一半资本开支。差距一直摆在那里，采购决策几乎不用讨论，Sun 能腾挪的空间也就越来越小。

Red Hat 和 IBM 立刻开始瞄准 Sun 的 Solaris 客户群。惠普和 SGI 则开始给自家专有硬件的客户提供迁移到 Linux 的选项，理由很务实：与其让客户流失，不如先保住客户关系。

2002 年服务器市场很难熬，但 Linux 机器仍在增长，而且是从 RISC 系统手里抢来的。Gartner 数据显示，2002 年 Linux 服务器硬件收入增长 63%，UNIX 硬件收入下降 11%。按绝对金额 UNIX 还是更大，2002 年为 170 亿美元，Linux 为 20 亿美元，但那只是因为 UNIX 卖的是高端机器、单价更高。压力已经很明显了：到 2004 年，Sun 服务器的平均售价从 22920 美元跌到 15860 美元，跌了 31%。

2003 年底，Linux 2.6 发布。视频说它是一个很有标志性的内核：速度、网络、最多 64 颗处理器的支持等各方面都有改进，可以算是第一个"企业就绪"的 Linux 内核。

![The Register 报道 Linux 2.6 发布](/img/2026/10/27/lintel-linux-2.6-register.jpg)

*图 31：The Register 对 Linux 2.6 发布的报道，"Penguins are go"。（原视频 00:38:53–00:38:58）*

时机也赶得正好：一批 Windows NT 4.0 用户正要进入升级周期。这些用户正处在"待嫁"状态，IBM、惠普、戴尔等厂商都在拼命把他们往 Linux 上拉。IBM 尤其卖力，培训了几千人，帮开发者把应用重写到 Linux 上，还给潜在的迁移客户大笔营销预算和折扣机器。

## 64 位：最后一堵墙

Intel 很早就希望 Linux 支持 64 位，也就是 IA-64，或者说 Itanium。1999 年 4 月，Intel 启动了 Project Trillian，这是一个多家公司组成的联盟，成员可以在保密条件下拿到 Itanium 原型，用来开发 Linux 移植版本。2000 年 2 月，项目提前向社区发布了 IA-64 Linux 源代码。视频称 Trillian 是开源软件开发史上的一个里程碑。不过 Itanium 最终没能取代 32 位 x86，只是惠普确实用它替换了自家专有 UNIX 变体所用的处理器。

真正开启 64 位过渡的是 AMD，不是 Intel。2003 年中，AMD 推出了开创性的 Opteron 系列芯片；2004 年，Intel 发布 Nocona Xeon，用的正是 AMD 那套向后兼容的 64 位扩展。

![AMD Opteron 处理器](/img/2026/10/27/lintel-amd-opteron.jpg)

*图 32：AMD Opteron 处理器。它用向后兼容的方式把 64 位引入 x86 生态，成为压垮 UNIX 最后一道架构壁垒的产品。（原视频 00:37:38–00:37:43）*

64 位一直是高端 UNIX 系统对 x86 仅剩的优势之一，原因很具体：32 位 x86 最多只能寻址约 4 GB 内存，而数据库、科学模拟这类高端应用需要常驻内存的数据量远远超过这个上限。换到 64 位后，x86 系统能寻址几十甚至几百 GB 内存。

![32 位与 64 位地址空间](/img/2026/10/27/lintel-address-space.png)

*图 33：地址空间是高端应用的一道硬性门槛。把 4 GB 的墙拆掉之后，UNIX 在架构层面最后的结构性优势也随之消失。*

一开始有人觉得 Intel 采用这套 64 位方案只是权宜之计，是通往 Itanium 的过渡。但结果摆在那里：x86-64 砸碎了 UNIX 周围的最后几堵墙。用视频的话说，Lintel 的"蛮族"已经进了城堡。

## Windows 的反击：Active Directory

面对 Linux 的攻势，微软一开始打的是营销战，核心论点是"大家已经在用 Office 了，与其折腾迁移，不如直接买 Windows Server 许可证"。2004 年，它发起了一场叫"Get the facts"的营销活动，发布了一批声称 Windows 优于 Linux 的研究，这些研究很快招来争议，被指不够中立，甚至可能误导。

视频作者认为，真正管用的不是营销，而是一款叫 Active Directory（AD）的产品带来的深度锁定。Stratechery 的 Ben Thompson 后来称它是"有史以来最有价值的免费产品之一"。

AD 随 Windows 2000 一起发布，负责对一个 Windows 网络里的所有用户和资产做认证和授权：推送更新、按组织架构给用户组分配安全权限、验证身份。落到日常运维上，管理员可以给新上任的经理开账户、验证凭据、授予相应工具的权限；用户用一套凭据就能登录各个系统；一堆零散的 Windows 机器被整合成一个能统一管理的组织。

![Windows 2000 的 Active Directory 管理界面](/img/2026/10/27/lintel-active-directory.jpg)

*图 34：Windows 2000 中的 Active Directory 用户和计算机管理界面。（原视频 00:40:04–00:40:08）*

要害在于，AD 让微软握住了"身份"这一层。身份深深嵌在组织内部，切换成本也就远远不止"换个操作系统"：要换的不只是服务器系统，还有整个组织的账号体系、权限模型和运维流程。竞争的层次就这样从"替换操作系统"被抬到了"重建组织身份体系"。

所以，尽管有人预言 Linux 会推翻微软，Windows Server 的销售却一直在涨。2005 年，Windows 的服务器收入首次追平 UNIX，第二年反超。Linux 也在继续增长，但它的增长主要不是从 Windows 那里抢来的，而是吃掉了 UNIX 的份额，再加上在 Windows 从没站稳过的新市场里扩张：超级计算、高性能计算、Web，以及 2010 年代的云计算。

![Gartner 统计的 UNIX 服务器安装量下滑](/img/2026/10/27/lintel-unix-install-base-gartner.jpg)

*图 35：2011–2017 年 UNIX 服务器安装量与占比的持续下滑。即便在被 Linux 击败十年之后，UNIX 也没有完全消失，但下降趋势从未逆转。（原视频 00:41:41–00:41:46）*

## 结论：输在商业模式，不是技术

此后几年，UNIX 服务器的销量缓慢下滑，但没有彻底消失。直到今天，仍有客户在用 Solaris、HP-UX 或 AIX，这些遗留应用大多集中在银行和医疗行业，对它们来说，迁到 Linux 要么太难，要么风险太高。

那 UNIX 为什么会输？视频作者的答案很明确：

> "I might propose that it had less to do with technology than business model. These vertically integrated kingdoms worked fine years ago until Intel arrived with its high volume economics."

（我认为这与技术关系不大，更多是商业模式的问题。这些垂直整合的王国在多年前运转良好，直到 Intel 带着它的高销量经济学到来。）

按他的叙述，先是 Windows NT 重创了 UNIX，然后 Linux 打得更狠，因为它能给客户 UNIX 有的一切，却没有锁定。等 Linux 足够好了，UNIX 厂商自己也只能转向 Linux。

把整条线索压缩一下，这场替代同时发生在三个层面上。

**成本层。** Intel 把 PC 的高销量飞轮带进服务器，同样性能的硬件价格降了一个数量级；SHV 参考设计又把整机成本压到 OEM 可以直接组装的水平。

**生态层。** GPL 让 Linux 成了一个所有公司都能一起投资、但谁也没法私有化的平台。IBM、Intel、Red Hat 这些利益并不一致的公司，因此能往同一个方向使劲。

**锁定层。** UNIX 的锁定来自专有软硬件的捆绑；Lintel 几乎没有锁定，操作系统、硬件、厂商都可以换。低锁定本身就是一种产品特性，采购决策因此变成了纯粹的性价比计算。

这三层互相加强：成本下降带来更多装机量，装机量吸引更多软件支持，软件支持又进一步拉低成本。UNIX 厂商的垂直整合结构偏偏进不了这个循环，它们的收入模型建立在"高单价、高锁定"上，任何降价都会直接吃掉利润。

还有一个反直觉的结果：Linux 赢了，UNIX 客户却没有因此被"解放"。在企业市场内部，微软用 Active Directory 建起了新的锁定层，让身份体系成了切换成本的主要来源。最后的格局是三分天下：Linux 拿下 Web 和新兴负载，Windows 守住企业身份和桌面协同，UNIX 退守少数监管严格或迁移风险极高的行业。

如果要从这段历史里带走几个判断，我会选这四个。

技术指标领先是必要条件，不是充分条件。Pentium Pro 的浮点一直落后于最好的 RISC，Linux 2.2 的 SMP 也很糟糕。它们能赢，靠的是"够用 + 便宜 + 不被锁定"这个组合。

治理结构是产品竞争力的一部分。GPL 决定了 Linux 能不能吸收大公司的贡献，同时又不被碎片化。

锁定层的迁移比技术替代更慢，也更关键。UNIX 的技术劣势在 1998 年就很明显了，但它真正退出主流花了十多年；同样，Linux 在服务器上占了上风，也没能撼动 Active Directory 建起的锁定。

伙伴的动机要单独拎出来看。Intel 支持 Linux，根子在于它对微软的结构性依赖。看懂这一点，比记住任何一场发布会都更能解释后来发生的事。

还没想清楚的问题，至少有三个。如果没有 AMD 的 Opteron，x86 的 64 位迁移会晚多久，Intel 的 Itanium 路线有没有可能成功？如果 GPL 换成更宽松的许可证（比如 BSD），Linux 会不会重演 UNIX 的碎片化？到了云计算时代，"锁定层"是不是已经从操作系统转移到了 API 和数据格式上，这和 Active Directory 的故事是不是同一个结构？
